# 部署、备份与运营

## 1. 本机运行

需要 Node.js 24 或更新的受支持版本、pnpm。首次运行：

```powershell
pnpm install --frozen-lockfile
pnpm setup
pnpm build
pnpm start
```

访问官网 `http://127.0.0.1:4173`，后台 `http://127.0.0.1:4173/admin`。初始账号保存在本地 `LOCAL-ACCESS.md`，不在公开网站或 README 内。`.env` 已存在时初始化脚本保留原有配置，不重置密码；已有数据库也不覆盖既有账号。

开发时在两个终端分别运行 `pnpm dev:server` 和 `pnpm dev`，浏览器访问 5173 端口。API 代理到 4173。允许的开发 Origin 在 `.env` 中显式配置。

## 2. 配置清单

| 配置 | 用途 | 本机 | 正式环境 |
|---|---|---|---|
| HOST | 服务监听地址 | 127.0.0.1 | 容器内 0.0.0.0、外部由代理控制 |
| PORT | HTTP 端口 | 4173 | 由部署决定 |
| DATABASE_PATH | 数据文件 | ./data/cct.sqlite | 持久卷路径 |
| ADMIN_EMAIL | 首次管理员 | 独立本机账号 | 正式管理员邮箱 |
| ADMIN_PASSWORD | 首次密码 | 初始化生成随机值 | Secret 管理器提供，不进入镜像 |
| NODE_ENV | Cookie 等安全模式 | development | production |
| PUBLIC_ORIGIN | 允许的外部来源 | http://127.0.0.1:4173 | 真实 HTTPS 源站 |
| ALLOWED_ORIGINS | 额外明确来源 | 本机 Vite 地址 | 默认不加无关来源 |

部署时必须把 PUBLIC_ORIGIN 改为实际域名。若生产 Cookie 为 Secure，直接 HTTP 登录无法正确维持登录，需要 HTTPS 代理。不要关闭 Secure 来绕过正式环境 HTTPS。

## 3. Docker 交付

已提供 Dockerfile 与 compose.yaml。它们为部署配置，是否实际构建／启动以验收记录为准。

1. 在受控服务器配置正式 PUBLIC_ORIGIN、ADMIN_EMAIL、ADMIN_PASSWORD。
2. 执行 `docker compose build` 与 `docker compose up -d`。
3. 容器 4173 绑定主机 loopback，HTTPS 反向代理转发到该端口。
4. 数据写入 cct-data 持久卷；更新容器不要删除该卷。
5. 首次登录修改初始密码，给内容人员创建 editor 账号。
6. 验证 `/api/health`、登录、内容草稿／发布和真实咨询流程。

镜像以非 root 用户运行，包含健康检查，不复制本机 `.env`、凭据或数据库。本次未申请域名、未购买服务器、未对外发布未经企业确认的官网。

## 4. 上线前必须填入的真实信息

- 集团法定主体、品牌授权与正式联系方式。
- 可公开的业务能力、已上线服务、真实项目案例及合作方授权。
- 隐私政策的实际数据控制者、保存期限、权利请求渠道。
- 实际域名、HTTPS、备案等适用要求由部署地区和主体确认。
- 正式运维负责人、管理员、备份保存地点与告警收件人。

这些是上线所缺配置，不影响本机完整系统开发和验收。

## 5. 日常运营

发布内容：后台内容管理 → 新建／编辑 → 填写中英文 → 保存草稿 → 预览 → 发布 → 公开站点刷新核对。

处理需求：线索管理 → 新线索 → 查看原始描述 → 在实际联系后改为已联系 → 写跟进备注 → 根据业务情况标记有效或关闭。

账号维护：为每位员工设置独立账号；内容人员使用 editor；离职时停用账号；不要共享管理员密码。

## 6. 备份与恢复

执行 `pnpm backup` 会调用 SQLite 一致性备份 API，输出到 backups。业务数据和咨询包含个人信息，备份应与生产数据采用相同访问控制。当前提供手动备份命令，未替用户建立外部定时任务或异地备份服务。

恢复步骤：

1. 停止应用写入，记录恢复时间点。
2. 保留当前数据库及关联 WAL/SHM 文件，避免不可逆覆盖。
3. 将选定备份放回 DATABASE_PATH；确认文件访问权限。
4. 启动服务并执行数据库完整性检查。
5. 验证管理员登录、已发布内容、咨询数量和最新操作记录。

## 7. 运行边界与扩展

当前为单实例应用。多实例之前迁移服务端数据库、共享会话／限流与对象存储。静态前端可交给 CDN，但后台和 Cookie 的同源设计需要保留。业务咨询量增大时为列表增加服务端分页与导出流程。长期运营建议接入集中日志、监控告警、恢复演练、MFA 或企业 SSO。

测试以自动行为测试和桌面／手机浏览器验收为准，未进行生产压力测试、第三方渗透测试或企业合规审计。
